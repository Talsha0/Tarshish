Tarshish Engine · setup roadmap

From a fresh checkout to a running PoC, then to a product.

Tick each step as you finish it. Every step ends with a check you can run, so a tick means "I saw it work", not "I think I did it". Your ticks are saved in this browser. This browser is not saving progress for local files.

Run every command from the tarshish_engine folder with the virtual environment active. Commands are written for Windows PowerShell; where Linux or macOS differs, the alternative is shown.

🧭 Two decoupled stages

Everything below follows the same two commands:

# Stage 1 · harvest — per category × store, once for every language, no AI cost
python main.py --harvest [--source temu_rapidapi|aliexpress_rapidapi] [--category gadgets]

# Stage 2 · publish — per category × language × content type, reads harvested products only
python main.py --publish --category gadgets --lang he [--content-types instagram_post,instagram_story]

Configuration has three parts, each a seed file in config/ and a tab of the dashboard: categories (search rules per store, in English), content types (generator + AI model per instagram_post, instagram_story, youtube_short, tiktok_video, telegram_post) and the social accounts matrix (category × language × platform ➔ page and .env variable names).

✅ Working and tested

  • Engine core, CLI and SQLite store
  • Two-stage engine: harvest per category × store, publish per category × language × content type
  • Two mock product sources (14 products, AliExpress and Temu)
  • Offline Hebrew / English captions
  • Console publisher, queue and worker
  • Streamlit dashboard: categories, accounts matrix, model routing, targeted runs, KPIs, storefront clicks
  • FindHub storefront: FastAPI backend, typo-tolerant search, Next.js site in Hebrew and English

🔌 Built, not yet run live

  • Claude and Gemini captions, Story overlay hooks, video captions

  • Telegram publisher
  • Instagram publisher (feed posts, Reels, Stories) and its live connection check
  • YouTube Shorts and TikTok Direct Post publishers and their live connection checks

Tested against stand-ins only. Phase 2 is their first contact with the real services.

  • Cloud media storage

Phase 1

Getting the PoC Running

Everything here runs on your own machine: no API keys, no accounts, no cost. Allow about half an hour, most of it waiting for packages to install. The last four steps bring up the FindHub storefront and need Node.js 20.9 or newer.

0 of 0

  1. From the repository root, move into the engine folder and confirm which Python you have.

    cd tarshish_engine
python --version

    Done when: Python reports 3.14 or 3.15, the versions the project is tested on. Anything from 3.11 should work but is untested.

  2. --clear wipes any old environment first. That matters: an environment breaks when the folder is moved or Python is upgraded, and this project has been through both.

    python -m venv --clear .venv
.venv\Scripts\Activate.ps1

    Linux / macOS: source .venv/bin/activate. If PowerShell refuses to run the activation script, run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once.

    Done when: your prompt starts with (.venv).

  3. This file includes the runtime packages plus pytest for the next step.

    python -m pip install -r requirements-dev.txt

    Written as python -m pip on purpose: on Windows 11 the plain pip command can be blocked (see "If something goes wrong" below).

    Done when: pip finishes with "Successfully installed" and no red error lines.

  4. The quickest proof that the install is healthy. The first run takes a minute or two while Python compiles the libraries; later runs take seconds.

    python -m pytest tests -q

    Done when: the last line reads … passed with no failures.

  5. Skip the copy if .env already exists. Leave every key empty for now: the PoC needs none. The file is git-ignored, so secrets you add later stay off GitHub.

    Copy-Item .env.example .env

    Linux / macOS: cp .env.example .env

    Done when: .env sits next to main.py.

  6. There is no separate migration command. The first start creates tarshish_engine.db and copies the three seed files — config/categories.yaml, content_profiles.yaml and social_accounts.yaml — into it. From then on the database is the source of truth.

    python main.py --list-config

    Edited a YAML file later? Push it into the database with python main.py --sync-config. An older database is upgraded in place on this first start; its history is kept.

    Done when: the list shows the gadgets and sports categories, the content types with their models (instagram_post on claude-sonnet-5-5, instagram_story on claude-haiku-5-5) and the account matrix, and the .db file exists.

  7. Stage 1 fills products from the offline Temu catalogue — once, for every language. Stage 2 then previews what each language's account would receive. Nothing is published, no AI is billed, and the dry-run writes nothing.

    python main.py --harvest --source temu_mock --category gadgets
python main.py --publish --category gadgets --lang he --content-types instagram_post,instagram_story --dry-run
python main.py --publish --category gadgets --lang en --content-types instagram_post,instagram_story --dry-run

    Warnings that the Instagram accounts lack credentials are expected: they come in the Instagram section.

    Done when: the harvest reports inserted 3; each dry-run shows instagram_post llm_text_gen [claude-sonnet-5-5] and instagram_story llm_story_gen [claude-haiku-5-5], Hebrew going to instagram_pub → gadgets and English to instagram_pub → gadgets_en, and ends with previewed 6 · failed 0.

  8. Leave it running in its own terminal and open a second terminal for the remaining steps.

    python -m streamlit run dashboard/app.py

    On Social Accounts, pick gadgets × he × type console as the platform, enter terminal as the handle (no variables needed) and Save account. This free local channel prints posts to the terminal; the console_post content type writes them.

    The shorter streamlit run dashboard/app.py is the same command; the python -m form is the one Windows does not block.

    Done when: http://localhost:8501 shows the four tabs, the matrix has a ✅ terminal cell for gadgets × Hebrew, and Run Pipelines & KPIs → ▶ Run pipeline (dry-run on) returns the Hebrew posts and Stories.

  9. A live run, but the only working account is your own terminal. This one does write to the database.

    python main.py --publish --category gadgets --lang he --content-types console_post --mode immediate --limit 1
python main.py --stats

    Run it again and you get the next product: an account never receives the same product twice in the same content type. --force overrides that.

    Done when: the stats show Published : 1 and the dashboard's Queue & Logs lists the post under pipeline gadgets_he.

  10. Production pacing puts 10 to 45 minutes between posts. For a quick demo, set these four values in .env:

    WORKER_ACTIVE_HOURS_START=0
WORKER_ACTIVE_HOURS_END=24
WORKER_MIN_DELAY_SECONDS=5
WORKER_MAX_DELAY_SECONDS=15

    Then queue the remaining products and start the worker. Stop it with Ctrl+C.

    python main.py --publish --category gadgets --lang he --content-types console_post --mode queued
python main.py --mode worker

    Done when: the worker prints the queued posts a few seconds apart and python main.py --stats shows an empty queue. Afterwards restore the four values (9, 22, 600, 2700).

# 3. Storefront website: what shoppers see                    (terminal B, leave running)
cd storefront
npm install

    Done when: http://localhost:8000/api/health answers "products": 14, and http://localhost:8000/api/docs lists the endpoints.

  3. In a third terminal. The first npm install downloads the packages and takes a minute or two.

npm install

    Done when: http://localhost:3000 opens the Hebrew storefront (right to left, prices in ₪) with fourteen deals, the EN switch shows the same page left to right, http://localhost:3000/he/c/sports shows the sports collection, and http://localhost:3000/he/p/1 opens straight into a product's Quick View.

If something goes wrong in Phase 1

[ENVIRONMENT ERROR] or an ImportError
The environment does not match your Python. Repeat steps 1.2 and 1.3.
"An Application Control policy has blocked this file", or pip / streamlit ends in "Access is denied"
Windows 11 Smart App Control refused an unsigned file from a freshly installed package. It is a setting of the computer, not a fault in the project, and it comes and goes. Use the python -m … commands exactly as written here, wait a minute and retry, then repeat steps 1.2 and 1.3. If a library keeps being blocked, the section "Windows Smart App Control" in tarshish_engine/README.md lists the options.
The tests all pass but pytest ends with a PermissionError
Make sure you run them from the tarshish_engine folder, where pytest.ini keeps test files inside the project.
[CONFIG ERROR]
The message names the exact variable in .env, or the file and row of config/ (for example categories 'gadgets' → min_rating), that is invalid. Fix it and rerun.
A publish run shows no cards and warns "no harvested … product is waiting"
Either nothing is harvested for that category yet (run --harvest), or that account already received every product in that content type. Add --force to preview them anyway.
The storefront says "The deals could not be loaded"
The website is up but the backend is not. Start it (step 1.12) and press "Try again". If the backend runs on another address, put it in storefront/.env.local as API_ORIGIN=… and restart npm run dev.
The storefront is empty, or the backend warns "no products yet"
Run step 1.11. A product is listed only when it has a category, a rating of 4.5 or more and at least 200 orders (STOREFRONT_MIN_RATING, STOREFRONT_MIN_ORDERS).
Hebrew looks reversed in the terminal
Most terminals do not render right-to-left text. The text itself is correct; check it in the dashboard.
Phase 2

Scaling to Production Product

From here on, steps cost money, touch real accounts, or need code that does not exist yet. Work through the four groups in order.

0 of 0

A · Real AI captions

  1. Put an Anthropic key, a Gemini key, or both in .env. Keys belong only there: never in the YAML file or the dashboard, which store variable names only.

    ANTHROPIC_API_KEY=sk-ant-...
GEMINI_API_KEY=...

    Confirm the key is picked up without spending anything:

    python main.py --publish --category gadgets --lang he --dry-run --force

    Done when: the Content line of each card reads offline-template [dry-run stand-in for claude-sonnet-5-5] (or claude-haiku-5-5 for Stories) instead of "not set".

  2. In the dashboard open Content Types & AI Models and set the LLM model of each content type. Shipped: claude-sonnet-5-5 for feed posts and TikTok captions, claude-haiku-5-5 for Story hooks and Telegram posts. Other choices: claude-opus-5-5, gemini-3.5-flash-lite, or type any model id. One change applies to every category and language. Then set the spending cap in .env:

    MAX_MONTHLY_AI_BUDGET_USD=5.0

    When the month's spend reaches the cap, every run that needs a paid model stops with exit code 3.

    Done when: the content-type table and python main.py --list-config show the models you chose.

  3. One product, one request. This is the first time the AI integration talks to the real service, so read the result carefully.

    python main.py --publish --category gadgets --lang he --content-types console_post --mode immediate --limit 1 --force
python main.py --stats

    First set console_post's model to a paid one (for example claude-haiku-5-5) in the Content Types tab, so the caption is written by the real service but only printed to your terminal.

    If the request is rejected, the error line names the HTTP status. A 401 means the key is wrong; a 404 means the model id is not available to your account.

    Done when: the caption is natural Hebrew rather than the template, the summary shows an AI cost above $0, and the stats show the same amount as monthly spend.

  1. In Telegram, message @BotFather, send /newbot and keep the token it gives you. Create a private test channel, then add the bot to it as an administrator with permission to post messages.

    Done when: you hold a bot token and the bot is listed among the channel's administrators.

  2. Add both values to .env. The chat id is @channelname for a public channel or the numeric id (it starts with -100) for a private one.

    TG_SPORTS_BOT_TOKEN=123456789:AA...
TG_SPORTS_CHAT_ID=@your_channel

    In the dashboard's Social Accounts tab, edit sports × he × telegram and replace the placeholder handle @my_sports_channel with your real channel name. Do it before the first post: the engine treats a renamed page as a new page and would post everything to it again.

    Restart the dashboard after editing .env; it reads the file at startup.

    Done when: the matrix shows the sports × Hebrew × telegram cell as ✅ ready.

  3. Harvest the sports category from the offline AliExpress catalogue, then publish one Telegram post.

    python main.py --harvest --source aliexpress_mock --category sports
python main.py --publish --category sports --lang he --content-types telegram_post --mode immediate --limit 1

    The mock products carry placeholder images and fake affiliate links. Keep this channel private until a real product source is in place.

    Done when: the post appears in your channel with a photo, the caption, the link, hashtags and the affiliate-disclosure line.

  4. Put a RapidAPI key and your affiliate tracking ids in .env (RAPIDAPI_KEY, TEMU_TRACKING_ID, ALIEXPRESS_TRACKING_ID), check each category's search rules in the Categories & Search tab, then harvest. Each category is searched once per store — publishing it in Hebrew and English costs no extra search.

    python main.py --harvest --category gadgets
python main.py --stats

    Another store is one file: plugins/sources/<name>.py extending BaseSource, then --harvest --source <name>. Nothing in core/ changes.

    Done when: the harvest names the provider that delivered, the stats list gadgets/temu and gadgets/aliexpress products, and a publish dry-run previews them.

  5. The publishers are built: plugins/publishers/youtube_pub.py (YouTube Data API v3, resumable upload) and plugins/publishers/tiktok_pub.py (Content Posting API, Direct Post). The youtube_short and tiktok_video content types and the (gadgets, he/en) accounts are in the seed files. What is left is credentials and rendering: work through Short-Form Video APIs Setup below.

    TikTok only lets audited apps post publicly, and YouTube locks uploads from unaudited API projects to private. Apply for both audits early; approval takes time.

    Done when: python main.py --publish --category gadgets --lang he --content-types youtube_short,tiktok_video --dry-run shows both accounts as ready.

  6. --publish queues by default (PUBLISHING_MODE=queued); the worker then posts with human pacing. Confirm .env holds production pacing and your audience's timezone:

    WORKER_TIMEZONE=Asia/Jerusalem
WORKER_ACTIVE_HOURS_START=9
WORKER_ACTIVE_HOURS_END=22
WORKER_MIN_DELAY_SECONDS=600
WORKER_MAX_DELAY_SECONDS=2700

    Done when: a run reports its items as queued, each with a scheduled time inside the active hours.

C · Background operations

  1. A small Linux server is enough. Clone the repository, build the environment, and bring .env over a secure channel (never through git).

    git clone <your-repo-url> /opt/tarshish
cd /opt/tarshish/tarshish_engine
python3 -m venv --clear .venv
.venv/bin/python -m pip install -r requirements.txt
chmod 600 .env

    Done when: .venv/bin/python main.py --stats runs on the server.

  2. Save this as /etc/systemd/system/tarshish-worker.service, replacing the user name with the account that owns the folder:

    [Unit]
Description=Tarshish queue worker
After=network-online.target
Wants=network-online.target

[Service]
User=tarshish
WorkingDirectory=/opt/tarshish/tarshish_engine
ExecStart=/opt/tarshish/tarshish_engine/.venv/bin/python main.py --mode worker
Restart=on-failure
RestartSec=30

[Install]
WantedBy=multi-user.target
    sudo systemctl daemon-reload
sudo systemctl enable --now tarshish-worker
systemctl status tarshish-worker

    Done when: the status is active (running) and logs/tarshish_engine.log contains "Queue worker started".

  3. The worker only publishes; something has to harvest and fill the queue. Open crontab -e and add two lines: a daily harvest (Stage 1, spends API quota once per category and store) and a publishing run (Stage 2, every category × language with an enabled account) three times a day:

    30 6 * * * cd /opt/tarshish/tarshish_engine && .venv/bin/python main.py --harvest >> logs/cron.log 2>&1
0 8,13,18 * * * cd /opt/tarshish/tarshish_engine && .venv/bin/python main.py --publish --mode queued >> logs/cron.log 2>&1
    Staying on Windows instead? Use Task Scheduler

    Replace C:\path\to with the real folder. The first two tasks harvest and fill the queue daily, the third starts the worker when you log on.

    schtasks /Create /TN "Tarshish harvest" /SC DAILY /ST 06:30 /TR "\"C:\path\to\tarshish_engine\.venv\Scripts\python.exe\" \"C:\path\to\tarshish_engine\main.py\" --harvest"
schtasks /Create /TN "Tarshish publish" /SC DAILY /ST 08:00 /TR "\"C:\path\to\tarshish_engine\.venv\Scripts\python.exe\" \"C:\path\to\tarshish_engine\main.py\" --publish --mode queued"
schtasks /Create /TN "Tarshish worker" /SC ONLOGON /TR "\"C:\path\to\tarshish_engine\.venv\Scripts\python.exe\" \"C:\path\to\tarshish_engine\main.py\" --mode worker"

    Done when: after the next scheduled time, logs/cron.log holds a run summary and --stats shows new items in the queue.

  4. The dashboard has no login. Anyone who can open it can edit categories, accounts and models, start runs and flush the queue, so never expose its port to the internet. Bind it to the server itself and connect through an SSH tunnel:

    .venv/bin/python -m streamlit run dashboard/app.py --server.address 127.0.0.1 --server.headless true
    ssh -L 8501:127.0.0.1:8501 you@your-server

    Done when: http://localhost:8501 on your own computer shows the server's dashboard, and the port is closed from outside.

  5. The whole state is one SQLite file. Copy it with SQLite's own backup command, which is safe while the worker is running, and schedule it nightly. Keep a copy of .env in a password manager.

    mkdir -p backups
sqlite3 tarshish_engine.db ".backup 'backups/tarshish-$(date +%F).db'"

    Done when: a dated backup file exists and you have restored one once to prove it opens.

D · Monitoring and growth

  1. Open the dashboard's Queue & Logs tab. For anything under Failed, read the error, fix the cause, then use "Retry all failed". The same from a terminal:

    python main.py --stats
python main.py --retry-failed

    Done when: you have gone a week with the Failed count returning to zero each day.

  2. Every run ends with an exit code: 0 fine, 1 something failed, 2 configuration error, 3 AI budget reached. Extend the cron line so a non-zero code reaches you, for example by mail or a ping to an uptime service:

    ... main.py --mode queued >> logs/cron.log 2>&1 || echo "Tarshish run failed" | mail -s "Tarshish alert" you@example.com

    Done when: you have triggered a failure on purpose (set the budget to 0 for one run) and the alert arrived.

  3. Views, clicks, conversions and revenue are not collected automatically yet. Once a week, open the KPIs & Budget tab, expand "Record a metrics snapshot" and enter the running totals reported by Telegram and your affiliate network for each post.

    Done when: the KPI tiles and the by-platform charts show real numbers.

  4. Write a small scheduled script that pulls the numbers from your affiliate network's reports and stores them with Database.record_metrics_snapshot(publication_id, views=…, clicks=…, conversions=…, revenue_usd=…). Values are running totals; the dashboard uses the latest snapshot of each post.

    Done when: the KPI numbers update without manual entry.

  5. On the KPIs & Budget tab compare Net profit with AI spend and look at how full the budget meter got. If spend outruns revenue, move a content type to a cheaper model (the "By content type" breakdown shows which one costs most) before raising the cap.

    Done when: you have made one model or budget decision based on a full month of numbers.

  6. Both are configuration, not code. A category: add it on Categories & Search with its English Temu / AliExpress keywords and press Harvest Now. A language: link one account per platform for it on Social Accounts (each with its own .env variable names). The products and model routing are shared, so nothing else is set up twice.

    Done when: python main.py --publish --category <id> --dry-run previews every language, each going to its own account.

  7. Do this after a real product source is in place (the demo catalogue's store links are placeholders). On the server run the backend without --reload and serve a production build of the website. The backend address is fixed when the site is built, so set it first.

    python -m uvicorn storefront_api.server:app --host 127.0.0.1 --port 8000

cd storefront
echo "API_ORIGIN=http://127.0.0.1:8000" > .env.local
echo "NEXT_PUBLIC_SITE_URL=https://your-domain.example" >> .env.local
npm ci
npm run build
npm run start

    Only the website (port 3000) needs to face the internet, behind HTTPS; it forwards /api to the backend itself. Each category then has a link ready for a social bio: https://your-domain.example/he/c/sports.

    Done when: a category link opened on a phone shows that collection, and a click on "Continue to Store" appears in the dashboard.

Publisher setup · Meta

Instagram API with Unified Login Setup (Meta Developer Portal)

Manual steps for the system administrator before instagram_pub can publish feed posts, Reels and Stories. All of it happens in Meta's portals except the last three steps. No Facebook Page is needed: a Meta Business Portfolio and a Professional Instagram account are enough. The engine calls https://graph.facebook.com/v21.0 with the token in an Authorization: Bearer header.

0 of 0

  1. In the Instagram app: Settings → Account type and tools → Switch to professional account, and choose Business or Creator. Then, in Meta Business Settings, open Accounts → Instagram accounts → Add and connect the account to your Meta Business Portfolio. No Facebook Page is required.

    Done when: the account is listed under Instagram accounts in your Business Portfolio and the Instagram app shows a professional dashboard.

  2. In the Meta App Dashboard (developers.facebook.com), create a Business app owned by the same Business Portfolio, or open the existing one. Under Add products, add Instagram API with Unified Login.

    Done when: the product appears in the app's left-hand menu.

  3. In the product's settings, create a Business Integration Configuration (Facebook Login for Business) that requests exactly these permissions:

    instagram_business_basic
instagram_business_content_publish

    While the app is in Development mode only people with a role on the app can authorise it. Meta's App Review for these permissions is needed only before other businesses use your app.

    Done when: the configuration is saved and lists both permissions.

  4. Either complete the Unified Login OAuth flow with the configuration above, or (recommended for a server) in Business Settings → Users → System users create a System User, assign it the app and the Instagram account, and Generate new token with the two permissions. System User tokens can be set never to expire.

    The account id (INSTAGRAM_BUSINESS_ACCOUNT_ID) is the Instagram account's numeric IG User id, usually starting with 178414. It is shown under the Instagram account in Business Settings, or returned by the Graph API Explorer for the token.

    Treat the token like a password: never paste it into config/social_accounts.yaml, the dashboard, a chat or a commit.

    Done when: you hold a token that Meta's Access Token Debugger shows as valid with both permissions, and the numeric account id.

  5. INSTAGRAM_ACCESS_TOKEN=EAAG...
INSTAGRAM_BUSINESS_ACCOUNT_ID=17841400000000000

    The (gadgets, he, instagram) account already references these two variable names; the English account (gadgets, en, instagram) uses INSTAGRAM_ACCESS_TOKEN_GADGETS_EN and INSTAGRAM_BUSINESS_ACCOUNT_ID_GADGETS_EN — add those too for a separate English page. Feed posts and Stories go to the same account: the instagram_post and instagram_story content types each ask for their own format. The engine reads every value from .env and masks the token as [REDACTED] in logs.

    Restart the dashboard after editing .env; it reads the file at startup.

    Done when: python main.py --publish --category gadgets --lang he --dry-run prints no "skipped" warning for instagram_pub.

  6. Meta's servers download the image_url / video_url themselves, so each URL must answer over HTTPS with no login, cookies or redirect to a login page. Feed images: JPEG, up to 8 MB, aspect ratio 4:5 to 1.91:1. Reels and Stories: MP4/MOV (H.264 + AAC), 9:16. Stories take no caption, so any price or "link in bio" text must be baked into the image or video.

    curl -I https://your-media-host.example/product.jpg

    Done when: the command above, run from outside your network, returns 200 with an image/jpeg (or video/mp4) content type.

  7. This checks the token, the Professional account type and both permissions. It never posts anything. The dashboard's Test Instagram Connection button on the Social Accounts tab runs the same check.

    python main.py --verify-instagram
python main.py --verify-instagram --category gadgets --lang he

    Done when: the report reads Connected as @your_account | BUSINESS | Permissions: ✓ instagram_business_basic, ✓ instagram_business_content_publish and ends with Ready for live publishing.

Publisher setup · Google & TikTok

Short-Form Video APIs Setup (YouTube Shorts & TikTok)

Manual steps before youtube_pub and tiktok_pub can publish. Both platforms take the video file itself (no URL pull), so the engine must render real MP4s. Secrets go only in .env (or the production platforms' secret settings); logs show them as [REDACTED].

0 of 0

A · YouTube Data API v3 (Google Cloud Console)

  1. In the Google Cloud Console (console.cloud.google.com), open the project picker and choose New project. One project serves every channel; its daily quota is shared between them.

    Done when: the new project is selected in the console's top bar.

  2. APIs & Services → Library, search for YouTube Data API v3 and click Enable.

    The default quota is 10,000 units a day and every upload (videos.insert) costs 1,600, so about 6 Shorts a day per project. The engine counts the units it spends, stops at YOUTUBE_DAILY_QUOTA_UNITS, and waits for the reset at midnight Pacific time after a quotaExceeded. Ask for more under IAM & Admin → Quotas.

    Done when: the API's page shows API enabled and a Quotas tab.

  3. APIs & Services → OAuth consent screen (Google Auth Platform). Choose External for ordinary Google accounts, or Internal if every channel belongs to your Google Workspace. Add the scope https://www.googleapis.com/auth/youtube.upload and, while testing, add the channel owners as test users.

    An External app left in Testing issues refresh tokens that expire after 7 days. Set the publishing status to In production before generating the token you keep. Separately, YouTube locks uploads from API projects that have not passed its compliance audit to private; request the audit through the YouTube API Services audit form before you rely on public Shorts.

    Done when: the consent screen lists the youtube.upload scope and shows the publishing status you chose.

  4. APIs & Services → Credentials → Create credentials → OAuth client ID. Pick Desktop app (simplest for the one-off token step below) or Web application with http://localhost as an authorised redirect URI. Download the JSON file (client_secret_….json) and keep it out of the repository.

    Done when: the client is listed under OAuth 2.0 Client IDs and the JSON file is on your machine.

  5. The engine ships a helper built on google-auth-oauthlib. It opens Google's consent page, requests https://www.googleapis.com/auth/youtube.upload with offline access, and prints the three .env lines. Sign in with the Google account that owns the channel (pick the brand channel if asked). Repeat once per channel.

    python -m plugins.publishers.youtube_pub --authorize path/to/client_secret.json

    No refresh token in the output? Remove the app at myaccount.google.com/permissions and run it again: Google only returns one on a fresh consent.

    Done when: the helper prints a YOUTUBE_REFRESH_TOKEN=1//… line.

  6. YOUTUBE_CLIENT_ID=1234567890-abc.apps.googleusercontent.com
YOUTUBE_CLIENT_SECRET=GOCSPX-...
YOUTUBE_REFRESH_TOKEN=1//0g...
# second channel (gadgets/en), referenced by the accounts matrix:
YOUTUBE_REFRESH_TOKEN_GADGETS_EN=1//0g...
# while testing:
YOUTUBE_PRIVACY_STATUS=unlisted

    Optional: YOUTUBE_CATEGORY_ID (28 Science & Technology, 22 People & Blogs; the default picks 28 for tech collections) and YOUTUBE_DAILY_QUOTA_UNITS.

    Done when: the Social Accounts tab shows the YouTube rows as ✅ ready.

B · TikTok Content Posting API (TikTok Developers Portal)

  1. Sign up at developers.tiktok.com and create (or join) an organisation for the business that owns the accounts.

    Done when: you can open Manage apps in the portal.

  2. Create an app, add the products Login Kit and Content Posting API, switch on Direct Post, and request the scopes user.info.basic and video.publish. Note the app's Client key and Client secret.

    Until TikTok audits the app, Direct Post only works with SELF_ONLY (private) visibility, the creator account must be private, and at most 5 creators may post per day. Submit the app for review in the portal to post publicly. Rate limit: 6 requests per minute per user token; the engine paces itself under it.

    Done when: the app shows Content Posting API with Direct Post enabled and the video.publish scope requested.

  3. Run Login Kit's OAuth flow (https://www.tiktok.com/v2/auth/authorize/ with scope=user.info.basic,video.publish) while signed in as the creator account, then exchange the returned code at https://open.tiktokapis.com/v2/oauth/token/. Keep both the access_token (valid 24 hours) and the refresh_token (valid 365 days).

    In sandbox only the target users you add to the sandbox can authorise, and posts stay private. A live, audited app can post publicly for any creator who authorises it.

    Done when: you hold an access token and a refresh token for each account in the matrix.

  4. TIKTOK_CLIENT_KEY=aw...
TIKTOK_CLIENT_SECRET=...
TIKTOK_ACCESS_TOKEN_GADGETS_HE=act....
TIKTOK_REFRESH_TOKEN_GADGETS_HE=rft....
TIKTOK_ACCESS_TOKEN_GADGETS_EN=act....
TIKTOK_REFRESH_TOKEN_GADGETS_EN=rft....
# until the app is audited:
TIKTOK_PRIVACY_LEVEL=SELF_ONLY

    With the client key, client secret and a refresh token present, the publisher refreshes the 24-hour access token itself before each post, so scheduled runs keep working. Affiliate posts can be marked as commercial content with TIKTOK_COMMERCIAL_CONTENT=your_brand or branded_content.

    Done when: the Social Accounts tab shows the TikTok rows as ✅ ready.

C · Video rendering prerequisite

  1. Install ffmpeg (it brings ffprobe) and switch rendering on. The ffmpeg_video_gen generator then renders up to four product photos into a 1080x1920 H.264 slideshow of about 12 seconds; storage uploads it and both publishers send the file.

    # .env
VIDEO_RENDER_ENABLED=true

ffmpeg -version
ffprobe -v error -select_streams v:0 -show_entries stream=width,height,codec_name:format=duration output/videos/<file>.mp4

    Before uploading, both publishers check each clip with ffprobe and refuse one that is not 9:16 or runs over 60 seconds, so a bad render fails fast instead of being rejected after the upload.

    Done when: ffprobe reports width=1080, height=1920, codec_name=h264 and a duration under 60 for a rendered file.

D · Verification

  1. Each check calls the real API without posting. YouTube: refreshes the OAuth token, confirms the youtube.upload scope and shows the quota budget. TikTok: validates the access token (refreshing it when possible), confirms Direct Post access and lists the privacy levels the creator may use. The Social Accounts tab has the same checks as Test YouTube connection and Test TikTok connection, next to each platform's last-run upload success rate.

    python main.py --verify-youtube
python main.py --verify-tiktok
python main.py --publish --category gadgets --lang he --content-types youtube_short,tiktok_video --dry-run

    Done when: both reports end with Ready for live publishing. and the dry-run shows youtube_pub and tiktok_pub as ready.
